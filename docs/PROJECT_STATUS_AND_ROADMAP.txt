SECTION 4 — THINGS THAT LOOK FINISHED BUT ARE STUBS
================================================================================

These are UI elements that exist, look correct, and do nothing (or the wrong
thing) when tapped. A user WILL find these within their first few minutes:

- Profile → "Set up backup": routes to the plain sign-in screen. There is no
  Google sign-in, no Drive integration, nothing backup-specific happens after
  sign-in.
- Settings → "Rate App": toast stub (reasonable to leave stubbed pre-launch).
- Auth (sign in / sign up): the UI, validation, and Clean Architecture
  plumbing are real and correct, but they point at
  https://api.example.com/v1/ — a placeholder domain, not a live backend.
  Nobody can actually create an account or sign in today.
- Search/Favorites/Document REST datasources, repositories, and usecases are
  fully coded, DI-registered, and completely unused dead code — every real
  screen bypasses them and reads the in-memory store directly. Not urgent to
  remove, but worth knowing they're not actually doing anything.
- "Share into Mantic" (ShareIntentService) only works on Android — sharing a
  PDF/photo into the app from iOS does nothing, since the plugin's iOS side
  needs a Share Extension added in Xcode (App Group, entitlements, Swift
  Package Manager linking) that can't be set up from a Windows machine.


================================================================================
SECTION 5 — SPEC FEATURES THAT DON'T EXIST YET AT ALL
================================================================================

Comparing against project_doc.md (your own technical spec), these are simply
not started:

- Custom per-category fields (field_schema). The spec calls for category-
  specific structured fields (e.g. Driving License: license no., DOB, valid
  till). Today every document has the same generic shape (title, category,
  tags, one expiry field) — no category-aware form fields anywhere.
- Document-completeness progress bar ("3 of 5 important documents added") on
  Home and Profile — not implemented; no is_essential concept exists on
  Category at all.
- AI embeddings and similar-document clustering (Phase 3) — AI chat search,
  auto-summaries, auto-categorization, and deadline detection are already
  live via Groq; embeddings/clustering specifically are not built.
- Backup/sync/Google Drive (Phase 1's optional backup + Phase 4's full sync):
  no google_sign_in, no Drive SDK, nothing.
- Shared vaults, voice notes (Phase 4): not started, expected at this stage.
- State management mismatch: the spec calls for Riverpod or Bloc; the app
  uses Provider throughout. Not wrong, just an open decision from CLAUDE.md
  that's still unresolved — worth explicitly deciding to keep Provider (it's
  working fine) rather than leaving it as a lingering "someday" migration.

================================================================================
SECTION 8 — ENHANCEMENT IDEAS BEYOND THE CURRENT SPEC
================================================================================

You asked what else could make this genuinely easier for a real person's
life, beyond what's already planned. These are scoped realistically, not a
wishlist — each has a rough effort/impact note so you can judge honestly
whether it's worth it.

HIGH IMPACT, LOW-TO-MEDIUM EFFORT:

- Home-screen quick-capture shortcut / widget. A single tap from the phone's
  home screen straight into the camera-scan flow, skipping Home entirely.
  Removes friction at exactly the moment someone has a physical paper in
  hand and needs to capture it before it gets lost.
- "Expiring soon" digest. A single weekly (not per-document-spammy) local
  notification: "3 documents expire this month" — links straight to a
  filtered list. Builds on the per-document expiry reminders already live
  (ExpiryNotificationService) for almost no extra cost, and gives people a
  reason to open the app regularly instead of only when they need something.
- Local export/backup-to-zip. Before full Google Drive sync exists, even a
  "export everything as a zip of PDFs to a folder I choose" button gives
  privacy-conscious users (or anyone who doesn't want a Google account) a
  real safety net. Much less engineering than full Drive sync.

MEDIUM IMPACT, MEDIUM EFFORT:

- Per-category "hide behind biometric" for sensitive categories (e.g.
  medical, financial) separate from the whole-app lock — lets someone hand
  their unlocked phone to a friend without exposing everything.
- Barcode / QR capture mode for things like warranty cards, membership cards,
  vehicle registration stickers — a different capture affordance than the
  page-scanner, reusing the same storage/tagging model.
- Bulk actions: multi-select documents (not just categories, which already
  supports multi-select) for bulk move/tag/delete/export. Natural extension
  of work already done for Manage Categories.
- "Renewal helper" links: for common expiring categories (passport, driving
  license, insurance), a category-level link out to the relevant official
  renewal site/portal. Small but genuinely reduces friction at the exact
  moment the reminder fires.
  
  

LOWER PRIORITY / LONGER HORIZON (fine to leave for later, listed for
completeness — don't let these distract from Sections 1–7):

- Family/shared vaults with read-only links (a lighter first cut of the full
  Phase 4 shared-vault system).
- Voice notes per document.
- Redaction tool (blur a field like an ID number) before sharing a document
  out of the app.
- On-device duplicate-scan detection (flag "you already scanned this").

WORTH ACTIVELY NOT BUILDING RIGHT NOW: further AI-adjacent features beyond
what's already live (chat search, auto-summaries, auto-categorization,
deadline detection). Embeddings/similar-document clustering specifically
still depend on ongoing API cost with no clear demand yet — keep those
behind the higher-priority gaps in Section 7.
