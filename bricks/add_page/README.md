# add_page

[![Powered by Mason](https://img.shields.io/endpoint?url=https%3A%2F%2Ftinyurl.com%2Fmason-badge)](https://github.com/felangel/mason)

Adds a new page/sub-flow to an **existing** feature module — e.g. adding
`change_password` alongside auth's existing `signin`/`signup` sub-flows,
the same way this template's own `presentation/` is split one folder per
sub-flow under a shared `data/`/`domain/`.

## When to use this vs. create_feature

- **create_feature** — scaffolds a brand-new feature module: its own
  `data/`, `domain/`, and a first page, wired into routes/DI.
- **add_page** (this brick) — adds one more page to a feature module that
  already exists, sharing that feature's existing `data/`/`domain/`
  instead of creating new ones.

## What it generates

```
lib/features/<feature>/
  domain/usecases/<page>_usecase.dart       (new — a stub, see below)
  presentation/<page>/
    views/<page>_page.dart
    viewmodels/<page>_viewmodel.dart
    widgets/
```

...and wires `<page>` into `route_names.dart`, `route_paths.dart`,
`app_router.dart`, and `injection_container.dart` — the same
marker-comment file surgery `create_feature` uses — and appends the new
page/viewmodel/usecase to the feature's own `<feature>_exports.dart`
barrel, so `app_router.dart`/`injection_container.dart` (and anything
else) can keep reaching it through the barrel import.

## What it deliberately does NOT do

The generated `<page>Usecase` is a stub: it depends on the feature's
*existing* `I<Feature>Repository`, but that interface doesn't have a
method for this new page yet — inserting a new method into an existing,
hand-written interface isn't something this hook attempts to guess at.
Instead the usecase compiles cleanly and throws `UnimplementedError` with
an actionable message until you:

1. Add a `<page>(...)` method to `I<Feature>Repository` (and its impl)
   with whatever request/response shape the page actually needs.
2. Replace the stub's `dynamic`/`NoParams` types with the real ones, and
   call the new repository method.


## Usage

```sh
mason make add_page
```
