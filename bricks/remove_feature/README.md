# remove_feature

[![Powered by Mason](https://img.shields.io/endpoint?url=https%3A%2F%2Ftinyurl.com%2Fmason-badge)](https://github.com/felangel/mason)

The inverse of `create_feature` — permanently deletes an entire feature
module: `lib/features/<name>/` and everything under it, plus all the
routing/DI wiring for **every page it contains**, not just the one page
`create_feature` originally generated.

It works this out by listing `lib/features/<name>/presentation/*/` —
each subfolder is one page, whether it's the feature's original page or a
sub-flow added later via `add_page` (e.g. auth's `signin`/`signup`) — and
removing each one's `route_names.dart`/`route_paths.dart`/
`app_router.dart`/`injection_container.dart` wiring before deleting the
feature directory itself.

To delete just one page/sub-flow from a feature that should otherwise
stay, use `remove_page` instead.

## Safety

- Requires `--confirm` (or answering "yes" to the interactive prompt) —
  without it, nothing is deleted; it only prints what *would* be deleted.
- Before deleting, scans the rest of `lib/` for any file outside the
  feature's own folder that still references it, and warns about each one
  — e.g. removing the `auth` feature will warn that
  `core/services/session_manager.dart` depends on `AuthEntity` and will
  need manual fixing.

## Usage

```sh
mason make remove_feature --feature_name auth --confirm
```

Or interactively:

```sh
mason make remove_feature
```
