# add_firebase

[![Powered by Mason](https://img.shields.io/endpoint?url=https%3A%2F%2Ftinyurl.com%2Fmason-badge)](https://github.com/felangel/mason)

Adds Firebase Authentication as a **drop-in alternative** to this
template's REST-backed auth — not a replacement, and not wired in as the
active implementation by default.

## Why this works cleanly

This template's `IAuthRepository` contract (`signinUser`/`signupUser`,
taking `LoginUser`/`SignupUser` and returning `Result<AuthEntity>`) is
already backend-agnostic: `AuthEntity` has no REST-specific shape, and
`LoginUser`/`SignupUser` only carry email/password/name — exactly what
Firebase's email/password auth needs too. So this brick can implement the
*same* `IAuthRepository` interface against Firebase instead of Dio, and
nothing above the repository boundary (usecases, viewmodels, views,
`SessionController`) needs to change either way.

## What it generates

```
lib/core/networks/
  exceptions/firebase_auth_exceptions.dart   (FirebaseAuthException -> AppException mapping)
  firebase/firebase_auth_helper.dart         (Firebase-Auth counterpart to DioHelper)

lib/features/auth/data/repository_impl/
  firebase_auth_repository_impl.dart         (implements IAuthRepository)
```

...and wires it up:

- `pubspec.yaml` — adds `firebase_core`/`firebase_auth`.
- `android/settings.gradle.kts` / `android/app/build.gradle.kts` — adds
  the `google-services` Gradle plugin, applied **only if
  `google-services.json` exists**, so a fresh clone still builds before
  Firebase is actually configured.
- `lib/main.dart` — adds `await Firebase.initializeApp();` before
  `await setupLocator();`.
- `lib/core/di/injection_container.dart` — registers `FirebaseAuth` and
  `FirebaseAuthHelper` (via a new `firebaseDependencies()` function), but
  does **not** change the active `IAuthRepository` registration.
- `lib/features/auth/auth_exports.dart` — exports the new repository impl.

## Exception handling

`FirebaseAuthHelper` never lets a raw `FirebaseAuthException` (or any
other exception) escape — every method catches it and throws this app's
own `AppException` vocabulary instead (`UserNotFoundAuthException`,
`WrongPasswordAuthException`, `EmailAlreadyInUseAuthException`,
`WeakPasswordAuthException`, `TooManyRequestsAuthException`,
`NetworkRequestFailedAuthException`, etc. — one subtype per
`FirebaseAuthException.code` this app distinguishes, defined in
`firebase_auth_exceptions.dart`). `FirebaseAuthRepositoryImpl` then runs
every call through the same `BaseRepository.execute()` every REST
repository already uses, so Firebase errors flow through the exact same
`Result<T>` -> `UseCaseExecutor` -> UI error-toast pipeline as REST
errors — a `ViewModel`/view can't tell the difference.

## What you still have to do yourself

1. Run `flutterfire configure`, or manually add
   `android/app/google-services.json` and
   `ios/Runner/GoogleService-Info.plist` from your Firebase console
   project — no generator can produce these, they're tied to your own
   Firebase project.
2. In the Firebase console, enable the **Email/Password** sign-in
   provider under Authentication -> Sign-in method.
3. Run `flutter pub get`.
4. Switch auth over to Firebase by editing `authDependencies()` in
   `lib/core/di/injection_container.dart`:
   ```dart
   // before:
   sl.registerLazySingleton<IAuthRepository>(
     () => AuthRepositoryImpl(dataSource: sl()),
   );
   // after:
   sl.registerLazySingleton<IAuthRepository>(
     () => FirebaseAuthRepositoryImpl(firebaseAuthHelper: sl()),
   );
   ```
   This is a deliberate one-line, manual step — running this brick never
   silently changes which backend your app's auth actually uses.
