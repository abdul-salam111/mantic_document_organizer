# remove_page

[![Powered by Mason](https://img.shields.io/endpoint?url=https%3A%2F%2Ftinyurl.com%2Fmason-badge)](https://github.com/felangel/mason)

The inverse of `add_page` — permanently deletes a page/sub-flow from an
existing feature: its `presentation/<page>/` folder, its usecase stub, and
all the wiring `add_page` (or `create_feature`, for a feature's main page)
added — the `route_names.dart`/`route_paths.dart` entries, the
`app_router.dart` route, the `injection_container.dart` dependency
function, and the feature's barrel-export lines.

Does **not** touch the feature's shared `data/`/`domain/` layer beyond the
one usecase file for this specific page. To delete an entire feature
module, use `remove_feature` instead.

## Safety

- Requires `--confirm` (or answering "yes" to the interactive prompt) —
  without it, nothing is deleted; it only prints what *would* be deleted.
- Before deleting, scans the rest of `lib/` for any file outside the
  page's own folder that still references it, and warns about each one —
  those will need manual fixing afterward (e.g. a hand-written import
  somewhere this brick doesn't know to update).
- Matches existing wiring by the page's generated string value/class name
  rather than assuming which brick created it, so it works whether the
  page came from `add_page` or was a feature's main page from
  `create_feature`.

## Usage

```sh
mason make remove_page --feature_name auth --page_name change_password --confirm
```

Or interactively:

```sh
mason make remove_page
```
